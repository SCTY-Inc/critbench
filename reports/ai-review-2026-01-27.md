# CritBench Code Review

## Code Quality

### Bug: `_collect_scores` defeats the purpose of multi-judge reliability analysis
**`score.py:282-299`** — The `_collect_scores` helper is supposed to collect per-judge scores for computing inter-rater reliability (Krippendorff's alpha, ICC). Instead, it copies the *same* final aggregated score to every model entry:

```python
final_score = dim_result.get("score", 0.5)
for model in models:
    all_scores[dimension][model].append(final_score)
```

This means the reliability metrics will always show perfect agreement because every judge gets assigned identical values. The comment on line 295-296 acknowledges the limitation. This is not a minor TODO — it renders the entire reliability/bias detection pipeline meaningless. Either the individual scorer modules need to return per-judge breakdowns, or this code shouldn't report reliability metrics at all (it currently reports fake reliability).

### Bug: `confidence` calculation can go negative
**`coherence.py:87`** — Confidence is computed as `1.0 - stdev(scores)`. Standard deviation for scores between 0 and 1 can reach ~0.5, but there's no floor. If judges wildly disagree (stdev > 1.0 from future score ranges or data errors), confidence goes negative. Should be `max(0.0, 1.0 - stdev)`.

### Bug: Redundant no-op in `_parse_coherence_evaluation`
**`coherence.py:248-249`** — The line:
```python
label = key.upper().replace("_", "_")
```
`.replace("_", "_")` does nothing. The same no-op is repeated on line 249. This looks like a find/replace artifact. The parsing logic works only because both sides of the comparison do the same no-op, but it obscures intent.

### API client not closed on exception paths
**`score.py:118-122`** — If `ModelAPIClient()` init succeeds but any scorer raises an exception, `api_client.close()` at line 248 is never reached. The client supports context manager protocol (`__enter__`/`__exit__`) but `score()` doesn't use it. An uncaught exception during scoring leaks an open `httpx.Client`.

### `score_with_rotation` creates ephemeral `ScenarioRotator` — usage tracking is lost
**`score.py:385-413`** — A fresh `ScenarioRotator` is constructed every call. Line 413 records usage (`rotator.record_usage(...)`) on this ephemeral object that's immediately garbage collected. The rotation tracking is stateless and never persists, so the contamination-prevention mechanism does nothing across runs.

### Global mutable state in `llm_mode.py`
**`llm_mode.py:7`** — `_LLM_ENABLED` is a module-level global, mutated via `set_llm_enabled()`. This is process-wide shared state with no thread safety. In any concurrent execution (parallel benchmark runs, test parallelism), one call to `set_llm_enabled(False)` silently disables LLM for all callers.

### Ethics scorer uses naive keyword matching
**`ethics.py:70-77`** — Substring matching on lowercased text means "24 hours" matches "available 24 hours a day" and "right now" matches "the right now-moment". This creates false positives on legitimate creative copy. The scanner also can't detect semantic dark patterns that don't use exact keyword phrases.

## Performance

### Synchronous serial API calls for multi-judge scoring
**`coherence.py:70-78`** — Each judge model is called sequentially in a `for` loop. With 3 judges and 6 dimensions, that's 18 serial HTTP round-trips at ~2-5 seconds each. Using `httpx.AsyncClient` with `asyncio.gather` or `concurrent.futures.ThreadPoolExecutor` would cut wall-clock time by roughly 3x.

### `httpx.Client` created per `ModelAPIClient` instance
**`client.py:32`** — Each call to `score()` creates a new `httpx.Client` (new connection pool). If running multiple benchmark scenarios, this misses connection reuse. The client should be passed in or shared.

## Architecture

### `score()` is a 100-line monolith with 10 boolean flags
**`score.py:52-279`** — The `score()` function takes 10 parameters (7 booleans), orchestrates file I/O, API initialization, anonymization, scoring, reliability, bias detection, CoT analysis, and debate. Each boolean adds a conditional branch. This should be decomposed — a `ScoringPipeline` class or builder pattern would make the feature toggles testable in isolation.

### Three scorers are stubs returning hardcoded 0.5
**`originality.py`, `adaptation.py`** — These return `{"score": 0.5, ...}` unconditionally. They're included in the weighted overall score at 15% and 10% respectively, meaning 25% of the benchmark result is always the same constant. Consumers have no way to know this from the API.

### `export/__init__.py` is empty
**`export/__init__.py`** — `__all__ = []` with no implementation. The CLI's `--out report.html` flag in `CLAUDE.md` implies HTML export should exist. This is either dead code or missing functionality.

### `score_with_rotation` not exported from `__init__.py`
**`__init__.py:21-23`** — `score_with_rotation` is defined in `score.py` but not included in `__all__` or imported in `__init__.py`. Users can't do `from critbench import score_with_rotation`.

### Hardcoded model map in client
**`client.py:53-57`** — The OpenRouter model mapping is a hardcoded dict inside `call_model()`. Adding or changing models requires editing this method. This should be configuration-driven (from `scoring.yaml` or constructor arg).

## Testing

### No tests for `score.py`, the core public API
There is no `test_score.py`. The `score()`, `score_with_rewards()`, and `score_with_rotation()` functions — the primary public API — have zero test coverage. These are complex orchestration functions with multiple code paths (LLM on/off, debate, anonymization, autofail).

### No tests for any of the 6 scorers
There are no tests for `coherence.py`, `judgment.py`, `voice.py`, `originality.py`, `ethics.py`, or `adaptation.py`. The ethics scorer has testable deterministic logic (keyword matching) that should be covered. The coherence parser (`_parse_coherence_evaluation`) handles string parsing that is fragile and needs edge-case tests.

### No tests for `client.py`
`ModelAPIClient` is untested. The `call_model` method does HTTP calls, response parsing, and model-name mapping — all of which can be tested with mocked responses.

### Debate test doesn't verify score convergence
**`test_debate.py:125-148`** — `test_run_debate_with_mock_responses` verifies the debate triggered and rounds ran, but doesn't assert that final scores moved toward the mock-returned value of 0.7. The test can't catch a bug where debate rounds run but scores aren't updated.

### Test coverage gap: ethics false positives
No test verifies that benign text containing dark-pattern substrings (e.g., "we'll be available 24 hours a day") correctly avoids autofail. This is the most dangerous gap given ethics triggers autofail → overall score = 0.

## Quick Wins

1. **Add `test_score.py` with offline-mode integration tests** — Test `score()` with `enable_llm=False` using fixture transcript/scenario files. Covers the most critical untested code path. Catches regressions in the orchestration layer without any API calls.

2. **Add `test_ethics.py` with false-positive cases** — The ethics keyword scanner is the only scorer that can cause autofail (overall = 0). Add tests for legitimate copy containing substring matches ("available 24 hours", "right now we're focused on...") to document and then fix false positives.

3. **Fix `_collect_scores` to propagate per-judge scores** — Change the scorer interface to return a `judge_scores: Dict[str, float]` alongside the aggregated `score`. Wire these through `_collect_scores`. Without this, the reliability/bias modules produce misleading metrics.

4. **Use `api_client` as context manager in `score()`** — Wrap the scoring block in `with ModelAPIClient() as api_client:` to guarantee cleanup on exceptions. One-line fix that prevents connection leaks.

5. **Parallelize judge API calls** — Replace the serial `for model in judge_models` loop in `coherence.py` (and presumably similar loops in other scorers) with `concurrent.futures.ThreadPoolExecutor`. The `httpx.Client` is thread-safe. This is the single biggest wall-clock performance improvement available.
