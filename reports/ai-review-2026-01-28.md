### Code Quality

**BUG: Single-judge confidence defaults to 1.0 (maximum)**
`benchmark/critbench/evaluation/scorers/coherence.py:87` (and same pattern in `judgment.py`, `voice.py`):
```python
confidences[key] = 1.0 - (statistics.stdev(scores) if len(scores) > 1 else 0.0)
```
When only one judge responds, `stdev` is skipped and confidence = `1.0 - 0.0 = 1.0`. This is semantically inverted — a single uncorroborated opinion should have *low* confidence, not maximum. This silently hides failures when 2 of 3 judges time out.

**BUG: `judgment.py` uppercases the entire line before parsing scores**
`benchmark/critbench/evaluation/scorers/judgment.py:248`:
```python
line = line.strip().upper()
```
Then `float(line.split(":")[1].strip())` parses the value. This works for pure numerics but will break on edge cases where the LLM returns something like `"0.8/1.0"` or `"0.8 (good)"`. Compare with `voice.py:293` which correctly uses `.split()[0]` on the original string. Inconsistent parsing across scorers.

**SMELL: Debate orchestrator is wired up but never invoked**
`benchmark/critbench/score.py:133` creates `debate_orchestrator`, and line 276 checks `if debate_results:`, but nothing ever populates `debate_results`. The `debate_orchestrator` variable is created and then abandoned. This is dead code in the main scoring path.

**SMELL: `score()` is a 120-line monolith with 6 repetitive scorer calls**
`benchmark/critbench/score.py:52-279` — each of the 6 dimensions is called, collected, and analyzed with nearly identical boilerplate (lines 148-204). This makes it easy to forget one step (e.g., ethics and originality skip `_collect_scores` and `_analyze_cot` respectively, possibly intentionally but indistinguishable from oversight).

### Performance

**Synchronous serial API calls to 3 models × 6 dimensions = 18 sequential HTTP requests**
`benchmark/critbench/evaluation/scorers/coherence.py:63-76` loops `for model in models` synchronously. With `timeout=120s` per call, worst case is 36 minutes. The `httpx.Client` is synchronous (`score.py:120` / `client.py:32`). Switching to `httpx.AsyncClient` with `asyncio.gather` for concurrent model calls within each dimension would cut wall-clock time roughly 3x.

**`_collect_scores` iterates all models to append the same value**
`benchmark/critbench/score.py:297-299`:
```python
for model in models:
    all_scores[dimension][model].append(final_score)
```
Beyond being semantically wrong (spec 002), it's also O(models) work to do nothing useful — every judge gets the same aggregated score.

### Architecture

**No structured return type for scorers**
Each scorer returns `Dict[str, Any]` with undocumented keys. `coherence.py` returns `breakdown`, `evidence`, `_reasoning`, `score`, `confidence`, and `banned_found` variously. There's no shared dataclass or TypedDict, so consumers in `score.py` must guess which keys exist (e.g., `dim_result.get("_reasoning", {})` at `score.py:313`).

**`client.py` model map is hardcoded**
`benchmark/critbench/api/client.py:53-57` — the OpenRouter model map is a static dict inside `call_model()`. Adding a new judge model requires editing this method. This should either be a config-driven map or use a passthrough (OpenRouter already accepts fully qualified names).

**`score_with_rotation` creates a `ScenarioRotator` per call with no persistence**
`benchmark/critbench/score.py:385` — a fresh `ScenarioRotator` is created each invocation. Line 413 calls `rotator.record_usage()`, but since the rotator is ephemeral, this usage is lost. The rotation tracking provides no actual anti-contamination benefit.

### Testing

**No negative-path tests for API client**
`client.py` has no tests (spec 007), but specifically: there's no handling or testing for HTTP errors beyond `response.raise_for_status()`. A 429 rate-limit, 500 server error, or malformed JSON from OpenRouter will propagate as an unhandled `httpx.HTTPStatusError` or `KeyError` on `data["choices"][0]`. No retry logic exists.

**Scorer parse functions are untested and fragile**
The `_parse_*_evaluation()` functions in each scorer (e.g., `coherence.py:236`, `judgment.py:238`, `voice.py:275`) handle free-form LLM output. These have no unit tests and are the most likely failure point — if an LLM changes its output format, scoring silently falls back to 0.5 defaults with no warning.

**Test assertions are sometimes too weak**
`test_rotation.py:112` — `assert len(new_constraints) > 0` only checks constraints aren't empty, not that rotation actually changed anything. Similarly `test_metrics.py:97-98` checks `alpha < 0.5` for "no agreement" — a more precise bound would be more useful.

### Quick Wins (new, non-duplicate)

1. **Fix single-judge confidence inversion** — Change `else 0.0` to `else 1.0` (so confidence = `1.0 - 1.0 = 0.0` for single judge). One-line fix in 3 files (`coherence.py:87`, `judgment.py:87`, `voice.py:99`). High impact on score reliability reporting.

2. **Wire up the debate orchestrator in `score.py`** — The orchestrator exists and is tested (`test_debate.py`) but never called from the main path. Add a loop after dimension scoring that checks `debate_orchestrator.should_trigger_debate()` and populates `debate_results`. ~20 lines of glue code to activate existing, tested functionality.

3. **Add a `ScorerResult` TypedDict/dataclass** — Enforce a contract on what scorers return. Prevents the `dim_result.get("_reasoning", {})` guessing pattern and makes it possible to type-check scorer outputs. Medium effort, prevents a class of runtime `KeyError` bugs.

4. **Make `ScenarioRotator` persist usage across calls** — `score_with_rotation` (`score.py:385`) creates a fresh rotator each time. Accept an optional `rotator` parameter or use a file-backed store so `record_usage` actually accumulates. Without this, the rotation feature is non-functional.

5. **Normalize scorer parsing to a shared utility** — All 3 implemented scorers have subtly different parsing logic (`coherence.py:248` vs `judgment.py:248` vs `voice.py:293`). Extract a shared `parse_llm_score(line, key) -> Optional[float]` that handles common formats consistently. Prevents the `judgment.py` `.upper()` inconsistency and makes parsing testable in isolation.
